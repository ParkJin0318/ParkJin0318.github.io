요즘은 한 번 만들어 놓고 끝나는 자동화보다, **매일 굴리는 개인용 에이전트**가 더 가치가 큰 것 같습니다.

다만 에이전트를 실제로 쓰기 시작하면 아래 문제를 자주 만나게 됩니다.

- 어디까지 자동화했는지 기억이 안 남
- 툴 연결이 끊겨서 흐름이 깨짐
- 로그가 흩어져서 원인 파악이 늦음
- 결국 귀찮아져서 안 쓰게 됨

이 글은 OpenClaw를 개발자 개인용 운영 도구로 세팅하는 방식과, 멀티 에이전트와 Notion 태스크 관리로 운영 루프를 만든 방법을 정리한 내용입니다.

> OpenClaw는 버전과 환경에 따라 명령어나 설정 파일이 조금씩 다를 수 있습니다.
> 정확한 커맨드는 `openclaw help` 출력 기준으로 맞춰주세요.


## 왜 OpenClaw인가

개인용 에이전트에 기대하는 형태는 대체로 비슷합니다.

- 텔레그램 같은 채널에서 할 일을 던지면, 에이전트가 알아서 처리
- 필요하면 여러 에이전트를 병렬로 돌려서 조사, 초안 작성, 코드 수정까지 분업
- 작업 기록이 파일로 남아서 다음날 이어서 하기 쉬움

OpenClaw는 이걸 운영 가능한 형태로 묶어주는 쪽에 강점이 있습니다.


## OpenClaw 구성요소

### 메인 에이전트

- 사용자가 대화 채널로 요청을 넣는 창구
- 작업을 쪼개고, 실행을 위임하고, 결과를 합칩니다

### 서브 에이전트

- 역할을 좁혀서 수행하는 실행 유닛
- 메인 에이전트가 `sessions_spawn` 같은 방식으로 생성하고, 결과는 메인에게 돌아옵니다

### 툴

에이전트가 실제로 할 수 있는 손입니다.

- 파일 읽기와 쓰기
- 셸 실행
- 웹 페이지 가져오기
- 메시지 전송
- 브라우저 자동화와 브라우저 릴레이

### 워크스페이스 파일

대화는 휘발되기 쉽습니다. 반대로 파일은 남습니다.

- `shared/MEMORY.md`는 중요한 결정과 정리를 남깁니다
- `memory/YYYY-MM-DD.md`는 일일 로그를 남깁니다
- `TOOLS.md`는 도구 사용법과 경로를 정리합니다
- `AGENTS.md`는 운영 규칙과 금지 행동을 적어둡니다

이 구조를 잡아두면 다음에도 같은 실수가 줄어듭니다.


## 핵심 운영 루프

OpenClaw를 꾸준히 쓰게 만든 건 기능보다 **운영 루프**였습니다.

1) 해야 할 일을 Notion에 쌓아둔다
2) 메인 에이전트가 Notion에서 다음 할 일을 가져온다
3) 일을 잘게 쪼개서 서브 에이전트에게 위임한다
4) 결과를 검증하고 Notion 상태를 업데이트한다

여기서 효과가 컸던 포인트는 두 가지입니다.

- 할 일은 한 곳 Notion으로 모은다
- 상태는 Backlog, Active, Done, Waiting으로 고정한다


## 서브 에이전트 역할 구성

역할을 미리 정해두면 병렬 작업이 깔끔해집니다.

- 개발 에이전트
  - 코드 수정, 리팩터링, 빌드와 테스트
  - 블로그 글 초안 작성 같은 글 작업도 이 쪽에 위임하는 편입니다
- 리서치 에이전트
  - 자료 조사, 링크 수집, 경쟁사 분석
- 비즈니스 에이전트
  - 기획 정리, 지표 분석, 가격 전략 초안
- 퀀트 에이전트
  - 정해진 루틴성 점검과 스캔
- 디자인 에이전트
  - 화면 구성 아이디어, 와이어프레임, UI 문서화

작업을 위임할 때는 이렇게 쪼개는 편이 안정적이었습니다.

- 조사
- 정리
- 실행
- 검증
- 기록


## 세팅 단계

### 1 설치와 상태 확인

```bash
openclaw gateway status
openclaw help
openclaw gateway --help
```

필요하면 재시작합니다.

```bash
openclaw gateway restart
```


### 2 기본 설정

중요한 건 무엇이 어디에 남는지 예측 가능하게 만드는 것입니다.

- 작업 디렉토리 고정
- 로그와 결과물이 남는 위치 고정
- 위험한 작업은 자동 승인 대신 확인하도록 설정


### 3 자주 쓰는 도구 조합

내 세팅에서 자주 등장하는 조합은 아래입니다.

- 웹 페이지 가져오기
  - 아티클 요약, 문서 확인
- 셸 실행
  - 리포 클론, 빌드, 테스트, 포맷
- 파일 읽기와 쓰기
  - 글 초안 생성, 수정, 요약 정리
- 브라우저 릴레이
  - 로그인과 2FA 때문에 자동화가 막힐 때, 이미 로그인된 브라우저 탭을 붙여서 처리
- Notion 태스크 스크립트
  - 태스크 생성, Active 전환, Done 처리

툴을 늘리는 것보다 더 중요한 건 실패했을 때의 복구 전략입니다.

- 타임아웃
- 재시도
- 실패 시 사람에게 질문하고 멈추기


## 마무리

OpenClaw 세팅에서 가장 중요한 건 도구 목록이 아니라, 멀티 에이전트와 태스크 관리로 운영 루프를 고정하는 것이었습니다.
한 번 세팅해두면 이후에는 Notion에 할 일을 쌓고, 메인 에이전트가 가져와서 역할별로 분업하는 흐름이 자연스럽게 돌아갑니다.
