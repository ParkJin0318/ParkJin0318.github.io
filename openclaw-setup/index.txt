요즘은 “한 번 만들어 놓고 끝”인 자동화보다, **매일 굴리는 개인용 에이전트**가 더 가치가 큰 것 같습니다.

다만 에이전트를 실제로 쓰기 시작하면 아래 문제를 자주 만나게 됩니다.

- 어디까지 자동화했는지 기억이 안 남
- 툴 연결이 끊겨서 흐름이 깨짐
- 로그가 흩어져서 원인 파악이 늦음
- 결국 귀찮아져서 안 쓰게 됨

이 글은 OpenClaw를 **개발자 개인용 운영 도구**로 세팅하는 방식(설치 → 기본 설정 → 툴 연결 → 운영 루틴)을 정리한 내용입니다.

> OpenClaw는 버전/환경에 따라 명령어나 설정 파일이 조금씩 다를 수 있습니다.
> 정확한 커맨드는 `openclaw help` 출력 기준으로 맞춰주세요.


## 왜 OpenClaw인가

개인용 에이전트에 기대하는 형태는 대체로 비슷합니다.

- 텔레그램 같은 채널에서 할 일을 던지면, 에이전트가 알아서 처리
- 필요하면 서브에이전트를 여러 개 띄워서 병렬로 조사/작성/수정
- 작업 기록이 파일로 남아서 다음날 다시 이어가기 쉬움

OpenClaw는 이걸 “운영 가능한 형태”로 묶어주는 쪽에 강점이 있습니다.


## OpenClaw 구성요소(개념 정리)

[다이어그램: 메인 에이전트 / 서브에이전트 / 툴 / 워크스페이스 파일]

### 1) 메인 에이전트(Main agent)

- 사용자가 대화 채널로 요청을 넣는 창구
- 작업을 쪼개고, 실행을 위임하고, 결과를 합칩니다.

### 2) 서브에이전트(Subagent)

- “조사만”, “초안 작성만”, “코드 수정만” 같이 역할을 좁혀서 수행하는 실행 유닛
- 메인 에이전트가 `sessions_spawn` 같은 방식으로 생성하고, 결과는 메인에게 돌아옵니다.

### 3) 툴(Tools)

- 에이전트가 실제로 할 수 있는 “손”
- 파일 읽기/쓰기, 셸 실행, 웹 페이지 가져오기, 메시지 전송 같은 기능들이 여기에 포함됩니다.

### 4) 워크스페이스 파일(= 파일 기반 메모리)

대화는 휘발되기 쉽습니다. 반대로 파일은 남습니다.

- `shared/MEMORY.md`: 장기 기억(중요한 결정/정리)
- `memory/YYYY-MM-DD.md`: 일일 로그
- `TOOLS.md`, `AGENTS.md`: 운영 규칙/툴 사용 가이드

이 구조를 잡아두면 “다음에도 같은 실수”가 줄어듭니다.


## 핵심: 멀티 에이전트 + Notion 태스크 관리

OpenClaw를 꾸준히 쓰게 만든 건 기능보다 **운영 루프**였습니다.

운영 루프는 단순합니다.

1) 해야 할 일을 Notion에 쌓아둔다
2) 메인 에이전트가 Notion에서 다음 할 일을 가져온다
3) 일을 잘게 쪼개서 서브에이전트에게 위임한다
4) 결과를 검증하고 Notion 상태를 업데이트한다

여기서 효과가 컸던 포인트는 두 가지입니다.

- **태스크의 단일 출처(SSOT)**: 할 일은 한 곳(Notion)으로 모읍니다.
- **상태 전이 규칙**: Backlog → Active → Done(또는 Waiting) 처럼 규칙을 고정합니다.

[이미지: Notion 태스크 DB 예시(Backlog/Active/Done)]


## 운영 루틴 (아침 1분 + heartbeat)

운영은 “한 번 설치”보다 “매일 굴리기”가 더 중요합니다.

### 1) 아침: 상태 체크(1분)

- 게이트웨이가 살아있는지
- 메시지 채널 연결이 정상인지

```bash
openclaw gateway status
```

필요하면 재시작:

```bash
openclaw gateway restart
```

### 2) heartbeat: 죽었을 때 알아차리기

자동화는 “잘 도는 날”보다 “죽은 날”이 문제입니다.
그래서 최소한 아래 중 하나는 두는 편이 좋습니다.

- 주기적으로 상태를 점검하고, 비정상이면 알림
- (선택) 일정 주기로 재시작

[이미지: 알림 채널(텔레그램)로 상태 알림이 오는 예시]


## 세팅 단계 (설치 → 기본 설정 → 툴 연결)

### 0) 워크스페이스부터 잡기

워크스페이스에는 아래 파일을 먼저 두는 편이 좋습니다.

- `TOOLS.md`: 사용할 수 있는 도구/스킬, 경로, 금지 패턴
- `AGENTS.md`: 에이전트 운영 규칙(위임 기준, 금지 행동 등)
- `shared/MEMORY.md`: 장기 기억
- `memory/YYYY-MM-DD.md`: 일일 로그


### 1) 설치/검증

환경마다 설치 방법은 달라질 수 있어서, 검증 커맨드를 기준점으로 둡니다.

```bash
openclaw gateway status
openclaw help
openclaw gateway --help
```


### 2) 기본 설정(작업 디렉토리/로그/권한)

중요한 건 “무엇이 어디에 남는지”를 예측 가능하게 만드는 것입니다.

- 작업 디렉토리 고정
- 로그/결과물이 남는 위치 고정
- 위험한 작업은 자동 승인 대신 확인하도록 설정


### 3) 자주 쓰는 툴 조합

- 웹 페이지 가져오기: 조사/리서치
- 셸 실행: 빌드/테스트/포맷
- 파일 읽기/쓰기: 초안/리포트/로그 남기기

툴을 늘리는 것보다 더 중요한 건, 실패했을 때의 복구 전략입니다.

- 타임아웃
- 재시도
- 실패 시 사람에게 질문하고 멈추기


### 4) 브라우저 Relay(확장 프로그램)로 로그인 문제 줄이기

브라우저 자동화는 실전에 들어가면 로그인/2FA에서 막히는 경우가 많습니다.

이럴 때는 격리된 자동화 브라우저 대신, 이미 로그인된 Chrome 탭을 붙이는 방식이 운영이 쉬운 편입니다.

[이미지: Chrome 확장 프로그램에서 Relay 뱃지 ON 상태]


## 실전 팁

### 1) 작업을 더 작게 쪼개기

한 번에 크게 시키면 검증이 어렵고 실패하면 원인이 흐립니다.

- 조사 → 정리 → 실행 → 검증 → 기록

이 흐름으로 쪼개고, 단계별로 서브에이전트를 붙이면 안정성이 올라갑니다.

### 2) 결과를 “파일로 남기기”

채팅에만 남기면 다음날 다시 처음부터 설명해야 합니다.

- 규칙은 `AGENTS.md`
- 툴 사용법은 `TOOLS.md`
- 결론/교훈은 `shared/MEMORY.md`
- 작업 흔적은 `memory/YYYY-MM-DD.md`
